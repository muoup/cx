# Tagged Unions

Tagged unions, also known as sum types, are structured data containing one of multiple different types and sufficient metadata to determine the current type, called a variant, at runtime. Generally, this is generated by the compiler as an internal struct containing the variant union and a sufficiently sized tag value to hold its current state, thus the term "tagged union."

They are declared with `enum union`, chosen because the type contains both an enumerated variant tag and a union payload:

```cx
enum union shape {
    circle :: f64,
    rectangle :: struct { f64 width; f64 height; },
    point :: void
};
```

While the language currently makes no guarantee about the exact memory configuration, the type above is often equivalent in layout to:

```cx
struct shape {
    union {
        f64 circle;
        struct { f64 width; f64 height; } rectangle;
        void point;
    } variant;
    u8 tag;
};
```

## Constructing Variants

Each variant is constructed through an associated function generated for the tagged union:

```cx
shape c = shape::circle(2.5f);
shape r = shape::rectangle({ .width = 5f, .height = 10f });
shape p = shape::point();
```

Variant constructors are addressable functions. This allows them to be passed
where a matching function pointer is expected:

```cx
shape (*make_circle)(f64) = shape::circle;
shape c = make_circle(2.5f);
```

Given a value of type `shape`, one may not directly access any of the variant payloads. Access requires first determining which variant the value contains, as described in [Pattern Matching](./pattern-matching.md).
